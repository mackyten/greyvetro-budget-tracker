| TASK-001 | The app has no user authentication: `firestore.rules` grants open read/write to anyone gated only by a hardcoded expiry (`request.time < timestamp.date(2026, 10, 31)`) because there is no `request.auth` to key rules off of, and `FirestoreBudgetRepository` (`lib/features/net_worth/data/firestore_budget_repository.dart`) reads/writes top-level `accounts`/`monthlyEntries` collections with no per-user scoping at all. `greyvetro-auth-hub` is Keycloak-based (OIDC), and Firestore security rules have no native way to verify a Keycloak/OIDC token directly — the standard bridge is a backend endpoint that verifies the incoming Keycloak access token, then mints a Firebase custom auth token (`admin.auth().createCustomToken(uid)`) for the Flutter client to sign in with via `signInWithCustomToken`. | A minimal backend (or Cloud Function) endpoint accepts a Keycloak access token, verifies its signature/issuer/audience against `greyvetro-auth-hub`'s realm, and returns a Firebase custom token for that user's `sub` claim.<br>The Flutter app signs in to Firebase Auth with that custom token before touching Firestore (`firebase_auth` dependency added).<br>`firestore.rules` replaced: the temporary time-boxed `allow read, write: if request.time < ...` rule is removed entirely, replaced by rules scoped to `request.auth.uid`.<br>`accounts` and `monthlyEntries` are re-scoped per-user (e.g. nested under `users/{uid}/...`) and `FirestoreBudgetRepository` updated to read/write under the signed-in user's path instead of top-level collections.<br>Existing seeded data (from `assets/seed/net_worth_seed.json`) migrated under the real user's uid rather than lost.<br>A signed-out client gets a permission-denied error from Firestore, verified against the Firebase emulator or a real deploy. | Hard |
